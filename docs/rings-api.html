Application API · version 0.3.0

One pump, three rings, no hidden threads.

STP is an encrypted UDP message transport: Noise IK handshakes, ChaCha20-Poly1305 sealed datagrams, Wirehair fountain-code parity for large messages, and rate-based congestion control in packets per second. The library starts no threads. All protocol work happens inside a Pump, and only while you call it. Your application talks to the pump through exactly three bounded, lock-free single-producer/single-consumer rings whose capacities you choose at setup: send and control carry work in, and receive carries one ordered stream of events out.

The application thread is the only producer of the send and control rings and the only consumer of the receive ring; the pump is the other end of each. Each ring operation is a constant-time ownership move with no retry loop, allocation or lock. Wakeups go through an eventfd (pump side) and a futex generation counter (application side).

1Quick start

This is the whole lifecycle: create an identity and address, construct the pump and endpoint, move the pump to a thread of your own that loops run_for(100 ms) until your cancel flag is set, connect, send, and drain events. It is adapted from examples/support/lockfree_common.rs and examples/lockfree_thread.rs.

Cargo: shielded_transport_pigeon
use shielded_transport_pigeon::{pump::port::lockfree::*, stp::*};
use std::collections::VecDeque;
use std::sync::{Arc, atomic::{AtomicBool, Ordering}};
use std::time::Duration;

// 1. Identity + address. The address is what peers dial: [ip]:port:magic1:key
let port: u16 = 9000;
let key = new_keypair_from_connect_magic1(CONNECT_MAGIC1_Noise_IK_25519_ChaChaPoly_BLAKE2s).unwrap();
let me = STPAddress::from(std::net::Ipv6Addr::LOCALHOST, port, &key);
println!("my address: {me:?}"); // Debug prints the parseable form

// 2. Construct. Synchronous; binds the UDP socket; starts no threads.
let (mut pump, mut ep) = new_pump_with_options(
    vec![key], port, None,                       // keys, UDP port, max_pps
    (1_000_000, 32 << 20, 32 << 20),            // send-buffer (target_us, min_bytes, max_bytes)
    2_000_000,                                   // max_message_size (required, <= 1 GiB)
    NetworkThreadOptions {
        rings: RingConfig { send: 128, control: 32, receive: 128 },
        ..Default::default()
    });

// 3. Your thread, your cancel flag. The library never spawns one.
let cancel = Arc::new(AtomicBool::new(false));
let stop = cancel.clone();
let worker = std::thread::spawn(move || {
    while !stop.load(Ordering::Acquire) { pump.run_for(Duration::from_millis(100)); }
});

// 4. Connect. true = request queued; the outcome arrives as an Event.
// Supply the parseable address printed by your peer as argv[1].
let remote_text = std::env::args().nth(1).expect("usage: example '[ip]:port:magic1:key'");
let remote = STPAddress::parse(&remote_text).expect("valid peer address");
let peer = remote.connection_key();
assert!(ep.try_connect(remote));

// 5. One loop: drain events, flush the outbox, park when idle.
let mut outbox: VecDeque<Vec<u8>> = VecDeque::new();
let mut connected = false;
loop {
    while let Some(event) = ep.try_recv() {
        match event {
            Event::Connected { peer: p, .. } if p == peer => {
                connected = true;
                outbox.push_back(b"hello over three rings".to_vec());
            }
            Event::Message { peer, data } => println!("{peer:?}: {} bytes", data.len()),
            Event::ConnectFailed { address, reason } => eprintln!("connect {address:?}: {reason:?}"),
            Event::Disconnected { peer: p, reason } => { if p == peer { connected = false; } eprintln!("gone: {reason:?}") }
            _ => {}
        }
    }
    // Send only after Connected: sends to a still-handshaking peer are dropped as unknown.
    while connected {
        let Some(msg) = outbox.front_mut() else { break };
        if !ep.try_send(peer, 0, Dscp::BestEffort, msg) { break; } // full: msg stays in the Vec
        outbox.pop_front();                                        // accepted: now an empty Vec
    }
    if !ep.park_until_ready() { break; } // false = closed and drained
}

// Shutdown: cancel, not flush.
ep.close();
cancel.store(true, Ordering::Release);
worker.join().unwrap();
Addresses and keys

An address is [IPv6]:port:magic1:public_key with both trailing parts URL-safe base64 without padding (IPv4 is written IPv4-mapped). magic1 selects the handshake: CONNECT_MAGIC1_Noise_IK_25519_ChaChaPoly_BLAKE2s, ..._BLAKE2b, or CONNECT_MAGIC1_PLAIN_TEXT, which is a mock scheme for development tests only. To dial an address the pump needs one of its own keypairs with the same magic1. A peer is named by ConnectionKey, which is address.connection_key(): IP, port and 15 bits of the key.

2Driving the pump

Pump owns the UDP socket and every bit of protocol state. Nothing runs between calls. The application API is entirely on LockfreeEndpoint, never on Pump.

MethodBehaviour
run_until(deadline: Instant)Does protocol work until deadline. When idle it blocks on the socket and the command wakeup instead of spinning, so a call generally returns at (or just after) its deadline. If entered at or after the deadline it returns at once and does nothing.
run_for(duration: Duration)run_until(Instant::now() + duration).
next_wakeup() -> Option<Instant>Earliest scheduled core work as of the last run. Commands or socket readiness can make work ready earlier. None means stopped, not “no timer”.

Style A: a dedicated thread

Loop run_for(100 ms) and check a flag you own. The 100 ms only bounds how quickly the loop notices your cancel flag; traffic wakes the pump immediately. A test checks that the worker exits well under 100 ms after the flag is set.

let join = std::thread::spawn(move || {
    while !stop.load(Ordering::Acquire) { pump.run_for(Duration::from_millis(100)); }
});  // examples/support/lockfree_common.rs: Worker::start

Style B: a game frame loop

Give the pump a small budget in each frame and drain events between frames. No endpoint call ever does transport work, so the rest of the frame is yours. From examples/lockfree_game.rs:

for frame_number in 0..400 {
    let frame = Instant::now();
    pa.run_until(frame + Duration::from_millis(1)); pb.run_for(Duration::from_millis(1));
    while let Some(event) = a.try_recv() {
        if matches!(event, Event::Connected { .. }) && !sent { send(&mut a, peer, b"message between frames".to_vec()); sent = true; }
    }
    while let Some(event) = b.try_recv() {
        if let Event::Message { data, .. } = event { println!("frame {frame_number}: {}", String::from_utf8_lossy(&data)); return; }
    }
    std::thread::sleep((frame + Duration::from_millis(16)).saturating_duration_since(Instant::now()));
}

A game-loop pump only advances during its budget, so timers, ACKs and retransmissions run at frame granularity. Throughput is bounded by how much budget you give it. The measured numbers in Performance are for a dedicated thread per pump.

Deadlines and forward progress

Guarantee: every call entered before its deadline makes progress

A run_until call entered before its deadline admits one eligible pending command and completes one unit of work, even if the deadline passes during clock calibration or preemption. One unit is one received datagram, one data send, one FEC completion or sweep entry, one connection send step, or eight bookkeeping units. An idle pass also counts as a unit. The cooperative overshoot bound is one admission plus one such unit.

  • Each protocol pass admits at most 32 commands. The deadline is checked before every admission except the first one, which is owed.
  • Protocol clock samples are taken at packet boundaries. Bookkeeping loops with no fresh sample re-check the clock every eight units.
  • A 150 µs active-retry quantum that is still running is never shortened. Only the owed command may be admitted inside it. The owed unit waits for a call made after the quantum ends.
  • Deadlines are converted to CLOCK_MONOTONIC_RAW once per call. At the maximum 500 ppm NTP slew, a 100 ms call has at most ~50 µs of drift.
Caveat: indivisible units

A native Wirehair encode, decode or recovery call cannot be preempted. Logical messages up to 1 GiB are split into codec units of at most 2 MiB, and one such unit can take a few milliseconds. OS scheduling and allocator latency are not hard real-time bounded. Explicit protocol telemetry also costs work proportional to the number of connections and queues. The test deadlines_under_encrypted_fec_load_deliver_messages drives 1 MB and 2 MB messages with 100 µs budgets and asserts a maximum overshoot below 50 ms.

3Send ring app → pump

pub fn try_send(&mut self, peer: ConnectionKey, queue: usize, class: Dscp, payload: &mut Vec<u8>) -> bool
ResultMeaning
trueAccepted. The allocation was moved into the ring with std::mem::take, so payload is now an empty Vec. You never hear about this message again: there is no admission or completion event.
falseThe ring is full, or the endpoint is closed or finished. payload is untouched: same pointer, same bytes. Retry later, or park first.

The pump takes messages from the head of the ring in FIFO order. It pops the head only when that peer’s protocol send queue has room for it (byte credit for queue). Otherwise the head stays in the ring and stats().send_head_blocked is incremented. Nothing is lost inside the pump to backpressure.

The head is popped and dropped and counted (no event) when:

ConditionCounter
Peer unknown, disconnected, or still handshaking (not yet Connected)send_dropped_unknown
Payload larger than the local max_message_size or the peer’s advertised maximumsend_dropped_oversized
queue >= send_queue_count for that connectionsend_dropped_invalid_queue
Admitted to the protocol send queuesent

queue picks one of the connection’s send_queue_count FIFO queues (default 1), which share bandwidth by equal-weight byte service. class is a Dscp traffic class (BestEffort, Af11, Af21, Ef). It never changes FIFO or round-robin scheduling, or congestion control.

Wait for Connected

A send to a peer whose handshake has not completed is dropped as unknown. Start sending to a peer after you see its Event::Connected.

4Control ring app → pump

pub enum Control { Connect(STPAddress), Disconnect(ConnectionKey) }

pub fn try_control(&mut self, control: Control) -> bool
pub fn try_connect(&mut self, address: STPAddress) -> bool     // = try_control(Control::Connect(address))
pub fn try_disconnect(&mut self, peer: ConnectionKey) -> bool // = try_control(Control::Disconnect(peer))

false means the ring is full or the endpoint is closed. In both cases the value is dropped, because it was passed by value. true means queued. Control commands go before sends at each admission. While any lifecycle event is waiting for receive-ring space, the pump consumes no control commands.

CommandOutcome
Connect, new peerHandshake starts. Ends in exactly one Connected or ConnectFailed { reason: TimedOut }. The handshake timeout is fixed at 30 s.
Connect, peer already present or handshakingConnectFailed { reason: AlreadyConnected }
Connect, no local keypair with that magic1, own key, or unusableConnectFailed { reason: InvalidAddress }
Disconnect, connected peerLocal state is removed at once, with no flush and no wire close. Produces Disconnected { reason: Local }.
Disconnect, pending connectConnectFailed { reason: Cancelled }
Disconnect, unknown peerNo event.
Disconnect is local cancellation

No close message is sent. The remote side finds out through its own liveness expiry (120 s with no ACK progress and no fresh authenticated packet), and it may reconnect at any time. Queued unsent data for that peer is discarded. Later sends to it count as send_dropped_unknown.

5Receive ring pump → app

pub fn try_recv(&mut self) -> Option<Event>

This is a single ordered stream of everything the application hears: lifecycle and data, for all peers. Popping an event also wakes the pump, because lifecycle events it holds back may now fit.

The event stream

pub enum Event {
    Connected     { peer: ConnectionKey, address: STPAddress, handshake_hash: [u8; 64] },
    ConnectFailed { address: STPAddress, reason: ConnectFailure },
    Disconnected  { peer: ConnectionKey, reason: DisconnectReason },
    Message       { peer: ConnectionKey, data: Vec<u8> },
}
pub enum ConnectFailure   { TimedOut, AlreadyConnected, InvalidAddress, Cancelled }
pub enum DisconnectReason { Local, TimedOut }

Connected is emitted for both outgoing and incoming associations. An incoming peer appears for the first time as Connected. handshake_hash is the Noise handshake hash, which you can use for channel binding.

7Parking & readiness

pub fn park_until_ready(&mut self) -> bool

This blocks the application thread on a futex generation counter. It returns immediately if there is already a receive event, a finished telemetry snapshot, or space in a ring whose last try_* failed because it was full. Otherwise it sleeps until one of those happens or the endpoint closes. It returns false only when the endpoint is closed or finished and no events remain to drain. Spurious wakes are allowed, so always re-check with try_* after it returns.

// tests/lockfree.rs: park_for_receive_and_close
loop {
    if let Some(Event::Message { data, .. }) = b.try_recv() { assert_eq!(data, b"park"); break; }
    assert!(b.park_until_ready());
}

For a custom wait you can get the raw notifier with readiness() -> Arc<Ready> and call Ready::wait(&self, observed: &mut u64). Start observed at 0. Spurious wakes and generation wrap at 232 apply. On non-Linux targets the wait falls back to 1 ms sleeps.

Cheap: stats() -> Stats

Expensive: protocol telemetry

ep.request_protocol_stats();                 // coalesces; never blocks the app
// ... later, in your loop (park_until_ready also wakes for it):
if let Some(u) = ep.try_protocol_stats() {        // Option<NetworkThreadPull>
    for (peer, s) in &u.connection_stats { println!("{peer:?} rate={} upps rtt={}us", s.cc_rate_upps, s.rtt_us); }
    println!("kernel rx drops: {:?}", u.thread_stats.kernel_rx_drops);
}

The pump collects the snapshot on its next pass and hands it over through a single atomic ownership slot, not another ring. Collecting it allocates, costs work proportional to connections and queues, and takes the core’s per-queue budget_sink mutex. Ordinary ring operations do none of these things. The snapshot carries per-connection CC/FEC counters (connection_stats), queue credit (unreliable_send_free_bytes) and thread counters (thread_stats). It carries no messages and no lifecycle state: those come only through the receive ring.

Legacy fields are always empty here

try_protocol_stats() returns the older NetworkThreadPull type. On this explicit telemetry path its message, connection and rejection fields (received_unreliable_messages, current_connections and the rejection lists) are always empty. Read only the telemetry fields. Messages and peer lifecycle come only from try_recv().

The three capacities are independent. They count slots, not bytes: a send or message slot holds a moved Vec<u8> of any size up to the maximum message, so there are no fixed byte slabs and no copies. Choosing ring sizes: send sets how many messages you can have in flight before try_send pushes back. The pipelined benchmarks used 8192 to keep a deep pipeline. receive should hold a burst of what you expect between two drains, because overflowing data is dropped. control rarely needs to be large.

10Threading & ownership

0
threads started by the library. Setup, protocol work and shutdown all run on threads you own.
1 + 1
owners: one Pump (any thread, one at a time) and one LockfreeEndpoint (any thread, one at a time).
  • Pump is Send. Move it to a worker thread, or keep it on the game thread. It is the only consumer of the send and control rings and the only producer of the receive ring.
  • LockfreeEndpoint is Send but deliberately not Sync (a PhantomData<Cell<()>> marker), and its mutating methods take &mut self. That is what makes the SPSC contract sound. You can hand it to another thread (tests move it into a parker thread and back), but you cannot share it. If several threads need to send, put your own queue or Mutex in front of it. Checked by handle_is_send_but_not_sync.
  • Each ring cursor has exactly one writer. Producers publish with Release, consumers observe with Acquire, and cursors are padded to their own 64-byte cache lines.

11Shutdown

  • ep.close() sets the stop flag and wakes both sides. After it, every try_* producer returns false.
  • Dropping Pump closes the UDP socket and publishes termination, even on unwind and even if the pump never ran. ep.is_finished() then reports true, and park_until_ready() returns false once events are drained.
  • Dropping the endpoint also closes.
  • Both of these cancel; they do not flush. Queued sends can be discarded, and lifecycle events are not promised for every queued request or association.
  • Stopping a dedicated thread: call close(), set your cancel flag, and join. The pump is dropped when its thread returns.

12Trade-offs & limits

Head-of-line blocking across peers

There is a single FIFO send ring. When the head message’s peer has no protocol send credit, it stays at the head, and messages queued behind it for other peers wait until that peer drains or is disconnected. stats().send_head_blocked shows it happening. The test fifo_credit_blocks_other_peer_until_head_disconnects demonstrates it: peer B is rate-limited to 1 pps with a 1-byte send buffer, a 1 MB message to B blocks a message to C, and disconnecting B releases it. If you mix a slow bulk peer with latency-sensitive ones, gate sends to the slow peer in your app (for example, keep your own per-peer outbox and use protocol telemetry’s unreliable_send_free_bytes), or run separate pumps.

  • No hard real-time bound. Overshoot is one admission plus one indivisible unit, and a native FEC unit (up to 2 MiB) can take a few ms. OS scheduling and allocation are outside the bound.
  • Data can be dropped on receive if the app does not drain. That is intentional, so the transport keeps ACKing. Size receive to fit.
  • No per-message send feedback. An accepted message has no delivery or failure event. Drops are visible only as counters.
  • Disconnect is local, with no wire close. The remote side times out after 120 s of no liveness.
  • Linux-specific pieces: futex parking and eventfd pump wakeups. Other targets fall back to 1 ms sleep polling in Ready::wait. The clock is CLOCK_MONOTONIC_RAW. All measurements here are Linux.
  • Congestion policy and handshake timer are fixed internally: not configurable through this API.
  • Handshakes: Noise IK (X25519, ChaChaPoly, BLAKE2s or BLAKE2b) selected by magic1. Plaintext is for tests only.

Where the ceiling is

One connection tops out around 250 MB/s (~2 Gbit/s). The limit is the sender pump thread running at ~100% of one core. Congestion control was not the limit: its target rate was 1.2–2.3× what was achieved. Sender pump profile:

crypto 28%
sendmsg/datagram 27%
FEC 19%
clock 12%
other

There is one sendmsg per datagram, and clock reads are expensive under HPET. In the small-message pump about 50% of the time goes to clock reads (HPET). For scale, plain TCP loopback with a single stream measured 23.4 Gbit/s on the same machine, but that has no crypto, no FEC and uses 64 KB segments, so it is a reference point rather than a like-for-like comparison.
